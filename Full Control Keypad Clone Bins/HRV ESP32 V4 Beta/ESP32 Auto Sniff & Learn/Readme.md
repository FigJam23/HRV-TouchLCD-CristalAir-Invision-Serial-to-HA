# HRV ESP32 V4 Beta - Auto Sniff & Learn

This folder contains two related ESP32 tools for HRV / Cristal Air / Invision style TouchLCD keypad bus work.

The goal is to allow an ESP32 to either:

1. **Passively sniff and learn** the original keypad serial traffic.
2. **Run as a standalone HRV fan controller** using either the default built-in command format or an imported learned JSON profile.

---

## Folder Structure

### `Auto Sniff and Learn tool`

Contains the Arduino `.ino` source for the passive sniffer.

Example file:

```text
HRV_Keypad_Passive_Sniffer_JSON_Builder.ino
````

This tool is used to connect an ESP32 to the HRV keypad bus in **RX-only mode**. It listens to the original keypad and builds a JSON profile containing the startup frames and fan command payloads.

Use this first if you are unsure whether your HRV keypad uses the same command format as the default firmware.

---

### `ESP32 Only Custom json startup`

Contains precompiled ESP32 `.bin` files for the standalone HRV fan controller firmware.

Example files:

```text
ESP32_RV21_2015_STANDALONE_IMPORTABLE_HRV_PROFILE.ino.bin
ESP32_RV21_2015_STANDALONE_IMPORTABLE_HRV_PROFILE.ino.bootloader.bin
ESP32_RV21_2015_STANDALONE_IMPORTABLE_HRV_PROFILE.ino.partitions.bin
ESP32_RV21_2015_STANDALONE_IMPORTABLE_HRV_PROFILE.ino.merged.bin
```

This firmware runs the ESP32 as a standalone HRV controller with:

```text
Wi-Fi setup
Web UI
OTA update page
Fan control
Setpoint control
Boost / Burnt Toast mode
MQTT support
Home Assistant discovery
Importable HRV JSON profile support
```

The main controller firmware has a web UI section where a JSON profile generated by the sniffer can be pasted and saved.

---

## Important Safety Notes

This project is experimental.

Only connect to the HRV/keypad bus if you understand the wiring and voltage levels.

For sniffing:

```text
ESP32 RX only -> HRV data/bus line
ESP32 GND     -> HRV negative / GND
ESP32 TX      -> NOT CONNECTED
```

Do **not** connect ESP32 TX to the HRV bus while sniffing.

The sniffer is designed to listen only. The controller firmware can transmit commands, so use care when connecting it to a live HRV controller.

## Default Serial Bus Assumptions

These tools are based on the observed HRV TouchLCD keypad bus:

```text
Baud:      1200
Serial:    8N1
Frame:     7E ... checksum ... 7E
Checksum:  negative sum of payload bytes
```

The JSON profiles store **payload only**.

Example full frame:

```text
7E 31 01 4F 32 1E 84 F0 5D 7E
```

Stored JSON payload:

```text
31 01 4F 32 1E 84 F0
```

The firmware adds the `7E` start/end bytes and calculates the checksum automatically.

## Passive Sniffer Tool

### Purpose

The sniffer learns what the real keypad sends during startup and fan changes.

It can detect whether the fan command format is:

```text
percent_template
```

or:

```text
fixed_frame
```

### `percent_template`

This means the keypad uses a real fan percentage byte, allowing 0-100% control.

Example:

```text
31 01 4E 1E 1E 84 F0 = 30%
31 01 4F 32 1E 84 F0 = 50%
31 01 50 64 1E 84 F0 = 100%
```

### `fixed_frame`

This means the keypad appears to use fixed low / medium / high command frames.

The controller firmware will map the slider like this:

```text
0%      = off payload if learned
1-30%   = low payload
31-75%  = medium payload
76-100% = high payload
```

## Sniffer Capture Process

1. Flash the sniffer `.ino` to an ESP32.
2. Connect ESP32 RX-only to the HRV keypad bus.
3. Open the sniffer web UI.
4. Click **Start boot capture**.
5. Power-cycle the HRV/keypad.
6. Wait for the boot capture to finish.
7. Click **Learn Fan Low**, then press low on the original keypad.
8. Click **Learn Fan Medium**, then press medium.
9. Click **Learn Fan High**, then press high.
10. Optionally learn fan off and fan on.
11. Export or copy the JSON profile.

The JSON can then be imported into the standalone controller firmware.

## Standalone Controller Firmware

The standalone controller firmware can run using either:

```text
Default built-in HRV command format
```

or:

```text
Imported JSON profile from the sniffer
```

If no JSON profile is imported, it uses the original built-in command format.

If a JSON profile is imported, it is saved in ESP32 NVS memory and retained after reboot or OTA update.

To return to default behaviour, use:

```text
HRV Protocol Profile -> Reset to Original Default
```

inside the web UI.

## Importing a Learned HRV Profile

In the controller web UI:

1. Open **HRV Protocol Profile**.
2. Paste the JSON exported from the sniffer.
3. Click **Import & Save Profile**.
4. Reboot the ESP32 before testing on the HRV bus.

The controller will then use the learned startup/fan payloads.

## Which BIN File Should I Flash?

If using a normal ESP flashing tool, the easiest file is usually:

```text
ESP32_RV21_2015_STANDALONE_IMPORTABLE_HRV_PROFILE.ino.merged.bin
```

This contains the application, bootloader, and partitions in one file.

If your flashing tool requires separate files, use:

```text
bootloader.bin
partitions.bin
main .bin
```

Use the flash addresses required by your ESP32 flashing tool.

Common ESP32 addresses are often:

```text
bootloader:  0x1000
partitions:  0x8000
app:         0x10000
```

Check your flashing tool before writing.

## Recommended Workflow

For a known working original RV21-style HRV keypad:

```text
Flash controller firmware
Use default profile
Test fan control
```

For an unknown keypad or heat-transfer model:

```text
Flash sniffer
Capture startup and fan commands
Export JSON
Flash controller firmware
Import JSON
Reboot
Test fan control
```

---

## Notes

This is a beta project.

Different HRV keypad revisions may use different startup frames or fan command formats. The sniffer/import profile system is intended to avoid hardcoding every possible keypad variation into the firmware.

If fan actual speed shows `0` or unknown, that does not always mean the command failed. Some keypad versions may report status differently. Use the sniffer to confirm what is actually being sent on the bus.
